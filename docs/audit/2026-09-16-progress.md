## Catálogo y cobertura

- Test con 251 activos, páginas de 37, sin duplicados y excluyendo inserciones posteriores al cursor inicial.
- Cinco órdenes adicionales recorren 121 activos con empates. Importación exacta, identidad por red/contrato, aislamiento de redes, rechazo de cursores inválidos, timestamps y persistencia comprobados.
- API HTTP probada sobre SQLite temporal y reabierta. Worker probado con backoff y leases: un propietario antiguo no puede confirmar el trabajo de otro.
- Navegador mostró pools de GeckoTerminal con contratos/fuente/timestamps, obtenidos al pulsar descubrimiento. No se certifica que todos tengan ruta desde USDC.
- El worker recorre ventanas upstream de páginas 1–10 y vuelve al principio; eso es una ventana de descubrimiento, no un índice exhaustivo ni un cursor blockchain. El catálogo persiste lo observado sin techo de 100 activos.
- El cursor fija el máximo ID y la hora de la consulta, pero los precios/liquidez pueden cambiar entre páginas. Los empates son deterministas; una clasificación cambiante puede mover resultados. La UI deduplica y refresca todas las páginas ya cargadas. Falta medir/definir snapshots de ranking bajo alta concurrencia.
- SQL usa selección del pool preferido y COUNT; no hay prueba de carga de millones de filas ni SLA.
